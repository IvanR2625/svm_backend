# SVM Microbiome Backend

A small [FastAPI](https://fastapi.tiangolo.com/) service that serves a pre-trained scikit-learn **Support Vector Machine (SVM)** classifier. You send it microbiome genus-level read counts and it returns a binary prediction with a probability.

## How it works

At startup, `main.py` loads three artifacts from `model/`:

| File | Purpose |
|------|---------|
| `svm_full_microbiome.joblib` | Trained SVM classifier (needs `predict_proba`, so it must be trained with `probability=True`) |
| `svm_full_microbiome_scaler.joblib` | Scaler fitted on the training data, applied before prediction |
| `genera_order.joblib` | List of genus names giving the feature order the model expects |

For each `/predict` request, the service:

1. Builds a zero vector with one slot per genus in `genera_order`.
2. Fills in the read count for each submitted genus it recognizes. **Unknown genera are silently ignored**, and any genus you leave out counts as `0`.
3. Scales the vector with the saved scaler.
4. Returns the SVM's predicted class label and the probability of class `1`.

## Project structure

```
svm_backend/

└── model/

```

## Getting started

### Prerequisites

- Python 3.10 or newer (the code uses `list[str]` type hints; it was developed on Python 3.13)
- pip

### Installation

```bash
git clone https://github.com/IvanR2625/svm_backend.git
cd svm_backend
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

> **Note:** `requirements.txt` doesn't pin versions. Joblib/pickle model files are tied to the scikit-learn version that created them. If you see unpickling errors or `InconsistentVersionWarning`, install the scikit-learn version the model was trained with (for example `pip install scikit-learn==1.x.y`).

### Run the server

```bash
uvicorn main:app --reload
```

The API runs at `http://127.0.0.1:8000`. On startup the console prints the loaded model type, scaler type, and how many genera it expects.

Interactive API docs (generated by FastAPI) are at:

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

## API reference

### `GET /`

Health check / welcome message.

**Response**

```json
{
  "message": "✅ SVM backend is live! Use POST /predict to send genera and read counts for prediction."
}
```

### `POST /predict`

Gets a prediction from genus read counts.

**Request body**

| Field | Type | Description |
|-------|------|-------------|
| `genera` | `string[]` | Genus names. They must match the names in `genera_order` exactly (case-sensitive). |
| `reads` | `number[]` | Abundance / read count for each genus, in the same order as `genera`. |

`genera` and `reads` are paired by position. If the lists are different lengths, the extra items in the longer list are ignored.

**Example request**

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
        "genera": ["Bacteroides", "Prevotella", "Faecalibacterium"],
        "reads":  [1520, 340, 875]
      }'
```

**Example response**

```json
{
  "prediction_label": 1,
  "prediction_probability": 0.8734
}
```

| Field | Type | Description |
|-------|------|-------------|
| `prediction_label` | `int` | Predicted class (`0` or `1`) |
| `prediction_probability` | `float` | Model's estimated probability of class `1` |

The meaning of class `0` and class `1` depends on the labels used in training.

## Using it from a front end

```javascript
const res = await fetch("http://127.0.0.1:8000/predict", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ genera: ["Bacteroides"], reads: [1520] }),
});
const { prediction_label, prediction_probability } = await res.json();
```

## Deployment notes

- **CORS:** CORS currently accepts every origin (`origins = ["*"]`). In production, replace that with your front end's URL in `main.py`.
- **Production server:** run without `--reload`, binding to the host and port your platform gives you, for example:
  ```bash
  uvicorn main:app --host 0.0.0.0 --port ${PORT:-8000}
  ```
- **Input validation:** the endpoint doesn't reject unknown genus names or mismatched list lengths. Validate input on the client, or add checks to `predict()`.

## Updating the model

To swap in a retrained model, replace the three files in `model/` with new ones made by `joblib.dump(...)`, keeping the same filenames. All three must come from the same training run: the scaler and the genus order have to match the features the SVM was trained on.
